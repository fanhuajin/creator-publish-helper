# Creator Publish Helper · 创作者投稿助手

Windows 键盘辅助工具：从本地文案文件读取标题、简介和标签，辅助填写 B站、抖音、小红书投稿页面。上传视频、封面设置、创作声明和最终发布由用户操作。

原快捷键版保留：`start.cmd` 启动，F5读取文案、F6按焦点填写、F9退出。新增 `bilibili_auto.cmd` 为独立B站自动化入口，可准备上传和表单，始终停在投稿前。抖音、小红书的完整自动化尚未完成，继续使用原快捷键版。

## 在另一台电脑安装

安装 Python 3.10 或更高版本（带 tkinter 的 Windows 官方安装版）与 Git。在 PowerShell 中运行：

```powershell
git clone https://github.com/fanhuajin/creator-publish-helper.git
cd creator-publish-helper
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

双击 `start.cmd` 启动，运行窗口需保持打开。也可直接运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 fill_helper.py
```

不需要公司电脑的 Python 路径或 E 盘视频目录。关闭助手后可重新启动；最近一次文案选择仅保存在本机，不提交到仓库。

## 快捷键

| 按键 | 操作 |
| --- | --- |
| F5 | 在资源管理器中单击选中文案文件，再按 F5 直接读取；成功后弹窗显示路径和标题 |
| F6 | 点击目标输入框后自动识别字段并填写；B站标题、简介、标签分别操作，抖音/小红书正文一次填写简介与关联话题 |
| F9 | 退出助手 |

F5 也支持选中一个目录，读取其中的 `发布文案.txt`。从其他窗口按 F5 会打开文件选择框。多选或文案格式错误时保持原选择。

平台依据当前浏览器窗口标题识别，字段通过 Windows UI Automation 读取当前焦点控件的输入提示、关联标签及同一行附近标签识别。不用固定坐标或字段高度猜测。无法识别、焦点变化或字段歧义时拒绝输入并弹窗提示。

B站点击标题、简介或标签输入框后分别按 F6；标签依旧追加，先手动清理旧标签。抖音、小红书点击标题框按 F6 填标题，点击正文按 F6 替换简介并追加 `#标签`，候选区域出现并稳定后按空格关联第一项，检测不确定时等待一秒。正文内已有内容与话题会被替换。

F7、F8 不再注册。F5 和 F9 保持原用途。浏览器需要向 Windows 暴露焦点输入框及其提示信息；部分浏览器版本、已填写后提示消失或平台可访问性缺失可能导致无法识别。这时不会自动降级为坐标点击或按操作顺序猜测。

对于抖音等未声明 textbox 角色的正文，读取原始可访问性树中的焦点节点；焦点为 Group/Custom 时，仅在已知编辑器类名或可写 TextPattern 证据存在时识别为正文，整页 RootWebArea 不当作正文。读取不到这些证据仍会停止。失败时 `focus_diagnostic.json` 保存本地焦点诊断，已排除 Git 提交；可能包含控件可访问名称，不上传。

话题模式需要英文输入状态，鼠标留在输入行附近。按住 Esc 可中止当前输入。执行时不要切换窗口、移动输入焦点或连续重复触发快捷键。

一次识别/填写完成前重复按 F6 会被忽略，不会排队再次输入；选择文案或错误提示期间重复的 F5/F6 也会清理。助手保持热键注册，避免 F6 传给浏览器导致焦点切换。F9 在当前处理结束后退出；需要立即中止输入时按住 Esc。此状态表示助手自己的任务是否运行，不监测你的手动打字或网页网络请求。

## 文案格式与批量操作

UTF-8 文本示例：

```text
标题：
我的视频标题

简介：
第一行简介
第二行简介

标签：
#舞蹈 #穿搭 #日常
```

三个章节必须非空，标签以空白分隔。同一文案可用于三个平台；下一条视频在资源管理器选中对应文案并按 F5，不用重启。每次填写重新读取文件，修改文案后无需重新加载。

## 使用限制

### B站独立自动化试用

安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，打开并登录B站视频投稿页面，双击 `bilibili_auto.cmd` 选择素材目录。目录中需有 `发布文案.txt` 与 `最终成片.mp4`；没有最终成片时只允许一个视频文件。

脚本复用 Windows MCP 0.8.5 的控件读取及鼠标键盘实现，运行时不调用模型、不发送截图。自动上传、等待上传完成、替换标题和简介、清理并重新添加标签；已有稿件时填写当前稿件，不重复上传。所有字段填写后回读或检查状态。鼠标会移动并点击，文本通过键盘 Ctrl+V 输入以保留表情，不使用网页赋值。

按页面从上到下处理：封面、标题、创作声明、分区、标签、简介、定时发布。启动时只回到页首一次，随后从当前位置向下查找字段，不逐项返回页首。目录名含 `_跳舞` 选择舞蹈，含 `_唱歌` 选择音乐；缺失或混合标记会停止。创作声明统一选择“含AI生成内容”，声明和分区已经正确时直接跳过选择。

封面优先 `B站4x3.png`，其次 `封面.png`、`封面.jpg`，两种比例使用同一张图片，保留上传后的默认居中和缩放，不点击顶部缩放滑块、不拖动图片。不同裁切比例仍需检查边缘文字。分区和定时的下拉列表可能在列表内部滚动，与页面向下处理相互独立。

启动时输入定时时间，格式为 `YYYY-MM-DD HH:MM`，按北京时间、5分钟间隔选择，范围为当前时间5分钟后至15天内。留空关闭定时，取消结束流程；也可传入 `--publish-at "2026-10-10 18:30"`，或者 `--publish-at ""` 不定时。日期和时间通过日历及滚动选项点击，最终回读确认。

最后仅定位“立即投稿”，不会点击提交，也不保存草稿。按住 Esc 或切换窗口会停止；失败弹窗显示原因。同一台电脑同时只允许一个任务，重复启动会提示等待。首次启动 uv 会下载 Python 3.13 和依赖。`bilibili_auto_status.json` 仅记录本地执行结果，不提交Git。

试用版依赖浏览器可访问性和B站当前表单布局；简介无提示时用表单标签与输入列定位。不可见、歧义或未确认编辑焦点时停止。当前Edge从空白上传页开始，上传视频、封面、标题、AI声明、舞蹈分区、标签、简介及提交前停止已完整实测通过。次日18:30定时选择已实测；音乐分区及跨月定时尚未实测。不要同时手动操作浏览器。可以只检查素材而不发送输入：

```powershell
uv run --python 3.13 --with windows-mcp==0.8.5 python -X utf8 bilibili_auto.py "E:\视频目录" --check
```

- 快捷键助手只支持 Windows，输入框由用户手动聚焦，不自动上传或发布；独立B站脚本可自动上传，始终不发布。
- 全局快捷键可能和其他程序冲突，注册失败会报错。
- F5 通过 Ctrl+C 获取选中文件路径，填写使用剪贴板，都会覆盖剪贴板。
- 候选检测是局部截图变化判断，不识别话题文字，也不保证关联成功；其他浮层、屏幕位置和平台改版可能影响检测。请检查实际结果。
- 截图只在内存比较，不保存或上传；不读取浏览器密码或登录数据。
- 使用 Windows 模拟键盘事件，不等同硬件键盘，不保证平台检测结果。
- 助手与浏览器建议都以普通权限运行。

检查文案解析、平台识别、焦点字段判定及候选图像判断，不发送键鼠输入。原本地版本的填写与快速话题模式经用户试用确认；本次 F6 焦点识别尚未进行真实网页验证，三个平台的控件可访问性需在目标电脑确认。
